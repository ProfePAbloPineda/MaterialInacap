Primero se controla el proceso, no el PLC

Problema de control

Un sistema recibe información del proceso, decide según una estrategia y actúa para llevarlo a un estado deseado.

Sensor→Controlador→Actuador

Tres clases de lógica

  • Combinacional: depende del estado actual.
  • Secuencial: depende también de estados anteriores.
  • Temporal: incorpora tiempos, retardos o duraciones.
Actividad inicial: describa el control de llenado de un estanque. Identifique objetivo, sensores, actuadores, estados, riesgos y qué debe ocurrir ante una falla.

Especificar evita programar supuestos

PreguntaEjemplo: estanque con bomba
¿Qué se desea?Mantener nivel entre límites sin desbordar ni hacer trabajar la bomba en seco.
¿Qué se mide?Nivel bajo, nivel alto, nivel analógico, feedback y estado térmico.
¿Qué se acciona?Bomba, válvula y alarma.
¿Qué permisos existen?Modo automático, protección sana, nivel de fuente suficiente.
¿Qué tiene prioridad?Parada de emergencia, fallas e interlocks.
¿Cómo se demuestra?Casos normales, límites, sensores discordantes, corte de energía y recuperación.
Error frecuente: comenzar con contactos y bobinas sin haber definido estados, prioridades ni condición segura.

Un PLC integra control, diagnóstico e interfaz de campo

Un controlador lógico programable es un equipo industrial que adquiere señales, ejecuta un programa de forma determinista, actualiza salidas y comunica diagnósticos.

PLC

I/O industrial, ciclo controlado, mantenimiento y diagnóstico. Adecuado para máquinas y procesos.

Relés cableados

Comprensibles en circuitos pequeños, pero difíciles de modificar, escalar y diagnosticar.

Microcontrolador

Flexible y económico, pero requiere diseñar acondicionamiento, protección, firmware y diagnóstico.

Idea clave: un PLC no es simplemente “un Arduino industrial”; es una plataforma completa de automatización con modelo de ejecución, I/O y herramientas de ingeniería.

La arquitectura explica lo que el programa puede hacer

Fuente→CPU + memoria↔Backplane↔I/O↔Red

CPU, reloj y watchdog

La CPU ejecuta tareas. El reloj ordena el tiempo y el watchdog detecta ejecuciones que exceden el límite previsto.

Memoria

Almacena programa, configuración, datos, estados retentivos, diagnósticos e imagen de proceso.

Backplane y módulos

Distribuyen alimentación y datos. La posición, compatibilidad y presupuesto de potencia importan.

Comunicaciones

Permiten programación, HMI, I/O remoto, variadores, supervisión y redes de control.

Compacto, modular o distribuido es una decisión de proyecto

ArquitecturaVentajaLimitaciónAplicación típica
CompactaMenor costo y montaje simpleExpansión limitadaMáquina pequeña
ModularConfiguración y expansión flexiblesMayor costo y espacioMáquinas medianas y procesos
DistribuidaReduce cableado de campo y acerca I/ODepende de red y diagnósticoPlantas extensas

Decisión técnica

Para escoger no basta contar puntos: considere tipo eléctrico, aislamiento, velocidad, resolución, ambiente, expansión, comunicaciones, seguridad y mantenibilidad.

El ciclo de scan transforma señales en decisiones

Leer entradas→Imagen de proceso→Ejecutar lógica→Actualizar salidas→Diagnóstico

Imagen de proceso

El programa normalmente trabaja con una copia coherente de entradas y salidas durante el ciclo.

Tiempo de respuesta

No es solo el tiempo del programa: incluye filtro de entrada, espera de tarea, ejecución, actualización de salida y respuesta del dispositivo.

Pregunta: si un pulso dura menos que el scan o el filtro de entrada, ¿el PLC podrá detectarlo? La respuesta define si se necesita una entrada rápida o interrupción.

IEC 61131-3 da un lenguaje común al software

LAD / LD

Representación gráfica basada en continuidad lógica. Muy legible para mando discreto e interlocks.

FBD

Flujo de datos entre funciones y bloques. Natural para señales, regulación y encadenamiento funcional.

ST

Texto estructurado de alto nivel. Eficaz para cálculos, arreglos, decisiones complejas y máquinas de estado.

No compiten: una aplicación bien estructurada puede combinar lenguajes según el problema que resuelve cada POU.

Los datos deben conservar significado y rango

FUNCTION

Entrega un resultado; idealmente sin memoria interna persistente.

FUNCTION_BLOCK

Tiene instancia y estado interno: temporizadores, motores o válvulas.

Regla: nombres como DI_NivelAlto, Cmd_Bomba y Alm_Sobrecarga explican intención mejor que M0, X3 o Bit_7.

LAD representa continuidad lógica, no cableado físico

|----[ Marcha ]----[/ Paro ]----+----( Motor )----| | | |----[ Motor ]-------------------+

Lectura de la red

  1. Marcha debe ser verdadero.
  2. Paro se evalúa negado.
  3. Motor se realimenta en paralelo.
  4. La bobina se activa si existe camino lógico.

Advertencia

Un contacto negado no define si el pulsador físico es NA o NC. El símbolo examina el valor lógico de una variable.

La parada y las fallas deben tener prioridad explícita.

Un ejemplo LAD completo separa orden, permisos y salida

Comportamiento esperado: la bomba parte por nivel bajo; se detiene por nivel alto, emergencia o protección; si no aparece feedback dentro de 3 s, se genera alarma.
Prueba: construya al menos seis combinaciones de entrada y prediga Solicitud, Permiso, Bomba y Alarma antes de simular.

Temporizadores y contadores necesitan una intención clara

BloqueComportamientoUso típico
TONActiva Q después de mantener IN verdadero durante PT.Confirmación, retardo de partida
TOFMantiene Q por un tiempo tras caer IN.Ventilación posterior
TPGenera un pulso de duración definida.Dosificación, señal breve
CTUCuenta flancos ascendentes hasta PV.Piezas producidas
Errores típicos: contar nivel en vez de flanco, reutilizar una instancia de temporizador para dos funciones o no definir qué ocurre al reiniciar el PLC.

FBD hace visible el flujo de una señal

SP−PV→SUB→LIMIT
−100…100→Salida

Función

Realiza una operación sin conservar estado propio: suma, resta, límite o conversión.

Bloque de función

Conserva estado en una instancia: temporizador, contador, PID o bloque de motor.

Buena práctica: junto con el valor analógico deben viajar su validez, calidad, alarma y modo de sustitución; un número por sí solo no informa si la señal es confiable.

ST resuelve cálculos y estados sin ocultar límites

(* Escalamiento 4–20 mA: RAW 5530…27648 a 0…100 % *)
SignalOK := (RawLevel >= 5200) AND (RawLevel <= 28500);

IF SignalOK THEN
    LevelPct := (DINT_TO_REAL(RawLevel - 5530) * 100.0)
                / DINT_TO_REAL(27648 - 5530);
    LevelPct := LIMIT(0.0, LevelPct, 100.0);
ELSE
    LevelPct := LastValidLevel;
    AlarmSignal := TRUE;
END_IF;
El ejemplo está completo: valida el rango, convierte tipos, escala, limita el resultado y define qué hacer si la señal deja de ser válida.

Una máquina de estados hace explícita la secuencia

CASE State OF
  0: (* DETENIDO *)
     Pump := FALSE;
     IF Auto AND Start AND PermissivesOK THEN State := 10; END_IF;
  10: (* ARRANCANDO *)
     Pump := TRUE;
     IF Feedback THEN State := 20;
     ELSIF StartTimeout.Q THEN State := 90; END_IF;
  20: (* FUNCIONANDO *)
     Pump := TRUE;
     IF Stop OR HighLevel THEN State := 0; END_IF;
  90: (* FALLA *)
     Pump := FALSE; Alarm := TRUE;
     IF Reset AND NOT Start THEN State := 0; END_IF;
ELSE State := 90;
END_CASE;

Las entradas digitales son circuitos, no solo bits

24 VDC de campo→Protección→Filtro→Aislamiento→Bit

PNP / sourcing

El sensor entrega positivo hacia la entrada. Muy habitual en automatización industrial.

NPN / sinking

El sensor conduce hacia 0 V. Requiere compatibilidad con el módulo y comunes correctos.

Diagnóstico: medir 24 V sin carga no garantiza un “1”. Revise corriente, umbrales, común, caída de tensión, filtro y LED del canal.
Actividad: dibuje el circuito completo sensor–fuente–entrada para un sensor PNP de tres hilos e identifique marrón, azul, negro y común del módulo.

La tecnología de salida debe corresponder a la carga

SalidaVentajasPrecauciones
ReléAC/DC, aislamiento, baja fugaDesgaste, rebote y menor velocidad
TransistorRápida, silenciosa, alta frecuenciaSolo DC, polaridad y corriente
TriacConmutación AC sin desgaste mecánicoCorriente de fuga y tipo de carga

Carga inductiva

Bobinas, contactores y válvulas almacenan energía. Use diodo, TVS o RC según DC/AC y tiempo de caída permitido.

Estado seguro

Una salida OFF no garantiza ausencia de energía: pueden existir fugas, contactos soldados o alimentación externa.

Las señales analógicas exigen una cadena completa

Magnitud→Transmisor→0–10 V / 4–20 mA→ADC + RAW→Unidad de ingeniería
Criterio0–10 V4–20 mA

No confundir: resolución indica el menor paso digital; exactitud, cercanía al valor real; repetibilidad, consistencia entre mediciones.

Escalar es convertir RAW en significado físico

Ecuación general:
EU = EUmin + (RAW − RAWmin) × (EUmax − EUmin) / (RAWmax − RAWmin)

Ejemplo resuelto

Transmisor 4–20 mA = 0–6 m. Módulo: 5530–27648 cuentas. Para RAW = 16589:

EU = 0 + (16589−5530)×6/(27648−5530) = 3,00 m

La escala no basta

Defina unidades, saturación, valores fuera de rango, diagnóstico, filtrado y comportamiento ante pérdida de señal.

Ejercicio: un transmisor 4–20 mA mide 0–10 bar. Calcule la presión para RAW=22000 usando los mismos extremos del módulo. Luego determine qué hará el programa con RAW=4000.

Seleccionar hardware es justificar cada restricción

CPU

  • Memoria y tiempo de ejecución
  • Tareas y reloj
  • Protocolos
  • Movimiento o PID

Fuente

  • Consumo por módulo
  • Carga de sensores
  • Margen y expansión
  • Corriente de irrupción

Módulos

  • Tipo eléctrico
  • Resolución/velocidad
  • Aislamiento
  • Temperatura y certificación
Desafío: a partir de la lista de I/O anterior, proponga CPU, fuente y módulos. Cada elección debe citar una característica requerida por el proceso, no una preferencia de marca.

Una lógica mantenible separa responsabilidades

Intención→Permisos→Interlocks→Comando→Feedback

Modos

Manual: acción controlada por operador.
Automático: secuencia del proceso.
Mantenimiento: pruebas autorizadas con restricciones.

Prioridad sugerida

  1. Seguridad y paro.
  2. Falla e interlock.
  3. Orden de detención.
  4. Orden de marcha.
  5. Retención de estado.
Manual no significa “sin protecciones”. Los interlocks esenciales siguen activos salvo procedimiento formal y autorizado.

Verificar no es lo mismo que validar

Verificación

¿Construimos la solución de acuerdo con la especificación? Revisión, simulación, prueba de bloques, I/O y secuencia.

Validación

¿La solución satisface la necesidad real del proceso y del usuario en condiciones de operación?

CasoPrecondiciónEstímuloResultado esperado
T01 Partida normalAuto, permisos OK, nivel bajoOrden de partidaBomba ON y feedback <3 s
T02 Sin feedbackFeedback desconectadoOrden de partidaParo y alarma a los 3 s
T03 EmergenciaBomba funcionandoActivar emergenciaSalida segura inmediata; rearme controlado
T04 Señal AI inválidaAutomáticoRAW bajo rangoAlarma, sustitución definida y paro seguro

El diagnóstico sigue la cadena física y lógica

  1. Asegurar: controlar riesgos antes de medir o forzar.
  2. Precisar: registrar síntoma, condición y momento.
  3. Alimentar: revisar fuentes, protecciones, comunes y módulos.
  4. Comparar: señal física, LED de canal y valor online.
  5. Seguir: comando → permiso → interlock → salida → feedback.
  6. Aislar: cambiar una variable por vez y registrar.
  7. Corregir: eliminar causa raíz y repetir aceptación.
Forzar no es reparar: un force puede ser útil para una prueba controlada, pero puede saltarse la intención del programa. Debe autorizarse, registrarse y retirarse.

Actividad integradora: estación de llenado

Problema

Controlar un estanque con transmisor 4–20 mA, sensores alto/bajo, bomba con feedback, modos manual/automático, alarma y parada segura.

Productos

  1. Descripción y estados.
  2. Lista de I/O eléctrica.
  3. Selección de CPU, fuente y módulos.
  4. Lógica LAD + ST o FBD.
  5. Escalamiento y calidad.
  6. Matriz de pruebas.
  7. Informe de fallas y correcciones.

Secuencia de trabajo

Riesgos y condición segura → I/O → hardware → escala analógica → permisos/comando/feedback → modos y estados → simulación → prueba punto a punto → matriz de casos → documentación.

La solución no se considera terminada porque “funcionó una vez”: debe ser comprensible, repetible, segura y verificable.

Cierre: del proceso a una solución demostrable

1. Comprender

Proceso, estados, señales, riesgos y prioridades.

2. Implementar

Hardware adecuado y lógica IEC 61131-3 estructurada.

3. Demostrar

Pruebas, diagnóstico, recuperación y documentación.

Preguntas de salida:
  1. ¿Por qué el scan influye en la detección de pulsos?
  2. ¿Cuándo elegiría LAD, FBD o ST?
  3. ¿Por qué 4–20 mA facilita detectar una falla?
  4. ¿Qué diferencia existe entre comando, salida física y efecto real?
  5. ¿Qué evidencia demostraría que la solución es operativa?
