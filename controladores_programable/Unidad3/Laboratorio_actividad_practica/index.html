Control remoto de un proceso mediante Python y PLC Delta SE

GII-TP v2.1 · Trabajo grupal con comprobación individual · 100 puntos · 8 horas pedagógicas sugeridas

1. Propósito de la evaluación

Implementar un proceso de partida/parada con contador de ciclos, ejecutado por un PLC Delta SE y supervisado desde el Mini SCADA en Python mediante Ethernet y Modbus TCP. La aplicación Python se entrega completa: se evalúa su utilización, lectura del código, integración con Ladder, diagnóstico y una modificación individual acotada.

Competencias: 3.1.1 programación de alto nivel; 3.1.2 interacción gráfica; 3.1.4 comunicación industrial; 3.1.5–3.1.7 adaptación de soluciones y trabajo colaborativo. 3.1.3 se aborda conceptualmente mediante separación control/potencia: este laboratorio no acredita implementación física de un elemento de potencia, al trabajar en simulación interna del PLC.

Condición previa: docente debe verificar Modbus TCP del PLC y correspondencia de registros PDU con direcciones D reales. No está validado que PDU 0 equivalga a D0. Si no existe compatibilidad de direcciones, configurar REG_* en Python antes de la evaluación. No utilizar una salida de potencia ni activar equipos peligrosos. La parada local implementada en Ladder tiene prioridad sobre la solicitud remota.

2. Equipos y archivos

Descarga del programa: Descargar mini_scada_python.rar (archivo situado en la misma carpeta que index.html). Descargue y descomprima el archivo antes de comenzar la actividad.

PC Windows, PLC Delta DVP-SE, fuente y cable de red, switch si es necesario, ISPSoft, Mini SCADA entregado (mini_scada.py, INICIAR_WINDOWS.bat, requirements.txt). Se permite usar un MiniSCADA.exe construido y probado por el docente.

3. Secuencia de trabajo

  1. Comprobar software: extraer mini_scada_python.rar, ejecutar INICIAR_WINDOWS.bat (Python 3.10+ e Internet para instalar dependencias la primera vez) o iniciar el ejecutable docente. Comprobar modo Simulación.
  2. Preparar el PLC: asignar IP conocida, habilitar servidor Modbus TCP y verificar mapa de holding registers correspondiente a cuatro variables de 16 bits.
  3. Desarrollar Ladder: al recibir comando 1 y si la condición de parada local está liberada, activar una memoria de marcha; si recibe comando 0, detener. En marcha continua durante cinco segundos, incrementar una vez el contador y reiniciar el temporizador de ciclo. Publicar estado real y alarma. No hacer depender la seguridad de Python.
  4. Integrar Python: seleccionar Modbus TCP, introducir IP y puerto 502, Unit ID correcto, conectar y demostrar intercambio real. Registrar pruebas y evidencias.
  5. Diagnosticar: con proceso detenido, provocar una falla de enlace de forma controlada (desconectar únicamente Ethernet); verificar indicación de pérdida de datos. Reconectar y comprobar el comportamiento del PLC.
  6. Evaluación individual: cada integrante realiza una pequeña modificación solicitada en el código fuente, la explica y demuestra su efecto en modo Simulación o, si procede, en la aplicación de laboratorio.
Contrato funcional: comando 1 = solicitud de marcha, 0 = parada; estado 1 = efectivamente en marcha, 0 = detenido; ciclos incrementa cada 5 s de marcha continua; alarma 0 = normal. El código recibido lee estado/ciclos/alarma como tres holding registers consecutivos. Los valores físicos de las direcciones se registran en el informe.
