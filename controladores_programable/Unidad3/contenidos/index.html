De la programación PLC al control mediante Python

4 horas pedagógicas · Unidad 3.1 · Guía de curación de contenidos, aplicación y preparación del laboratorio evaluado

1. ¿Qué aprenderemos?

Hasta ahora el PLC ha ejecutado la lógica de control y la HMI ha permitido operarlo. En esta unidad agregamos una aplicación creada en Python: una interfaz de computador que envía órdenes y muestra estados a través de Ethernet. El propósito no es aprender todo Python, sino comprender un programa existente y utilizarlo con un proceso industrial.

Resultado esperado: interpretar las instrucciones fundamentales de Python, ejecutar el Mini SCADA en modo de simulación e identificar cómo una aplicación gráfica intercambia información con un PLC por Modbus TCP.

El programa ya está desarrollado: mini_scada.py. En esta clase se estudia, ejecuta y modifica de forma acotada. No se solicita programar una interfaz desde cero.

2. Arquitectura del sistema

El PLC ejecuta las secuencias y decisiones del proceso. Python constituye el cliente de supervisión. Tkinter construye los botones e indicadores de pantalla. PyModbus transporta solicitudes de lectura y escritura. Ethernet es el medio de red y Modbus TCP es el protocolo de aplicación.

3. Python mínimo indispensable

Python es un lenguaje de alto nivel: permite trabajar con instrucciones legibles, sin gestionar directamente los detalles del hardware. Aquí bastan cuatro conceptos.

3.1 Variables

estado = 0               # 0 = detenido; 1 = marcha
contador = 3             # cantidad de ciclos
nombre = "Mini SCADA"    # texto

Las variables almacenan datos que el programa utiliza o muestra. En la aplicación real, REG_COMANDO, REG_ESTADO, REG_CICLOS y REG_ALARMA son constantes con direcciones de registros Modbus.

3.2 Condiciones

if estado == 1:
    print("EN MARCHA")
else:
    print("DETENIDO")

El bloque if evalúa una condición. La indentación define las instrucciones que pertenecen a cada rama. == compara; = asigna un valor.

3.3 Funciones y eventos

def detener():
    print("Solicitud de parada")

Una función agrupa operaciones. En la aplicación, presionar PARTIDA ejecuta self.send(1) y presionar PARADA ejecuta self.send(0). Un botón no controla directamente una salida física: emite una orden que el PLC debe interpretar.

3.4 Bibliotecas

import tkinter as tk
from pymodbus.client import ModbusTcpClient

Una biblioteca aporta funciones ya desarrolladas. Tkinter se usa para las ventanas y PyModbus para intercambiar registros. El Mini SCADA requiere PyModbus 3.11.3; el paquete de la unidad incluye un archivo requirements.txt.

4. Cómo ejecutar el programa en Windows

  1. Descomprima el ZIP del Mini SCADA en una carpeta local, por ejemplo Documentos\MiniSCADA.
  2. Compruebe que están mini_scada.py, INICIAR_WINDOWS.bat y requirements.txt en la misma carpeta.
  3. Si utiliza el código fuente, instale Python 3.10 o posterior. En Windows, habilite el lanzador py. Compruebe en la consola: py --version.
  4. Haga doble clic en INICIAR_WINDOWS.bat. La primera ejecución crea un entorno virtual e instala PyModbus (necesita Internet). También puede usar un MiniSCADA.exe construido y probado previamente por el docente.
  5. En la ventana elija Simulación, pulse Conectar / iniciar y después PARTIDA. Observe el estado y espere más de 5 segundos para ver el contador. Pulse PARADA.
Si no abre: revise el mensaje de consola y compruebe Python, el acceso a Internet en la primera instalación y que los archivos estén extraídos. No basta con ejecutar el archivo directamente dentro del ZIP. Si utiliza el .exe proporcionado por el docente, no requiere instalar Python.

6. El contrato de intercambio Modbus

El programa suministrado asume cuatro holding registers con direcciones PDU base cero. No presupone que una dirección D del PLC corresponda automáticamente a ese número Modbus: es indispensable contrastar la asignación real de registros en la configuración y documentación del Delta SE.

Constante PythonDirección PDUSentidoSignificado
REG_COMANDO0PC → PLC1 solicita marcha; 0 solicita parada.
REG_ESTADO1PLC → PC1 proceso activo; 0 detenido.
REG_CICLOS2PLC → PCContador entero de ciclos.
REG_ALARMA3PLC → PC0 normal; otro valor indica alarma.

El programa escribe REG_COMANDO mediante write_register() y lee en una sola petición tres registros consecutivos desde REG_ESTADO mediante read_holding_registers(..., count=3). La IP propuesta 192.168.10.20 y el puerto 502 son parámetros de ejemplo; la configuración real debe coincidir con el PLC.

7. Diferencia entre simulación y control real

En Simulación, una variable interna representa la marcha y el contador aumenta cada cinco segundos. No se utilizan PLC ni cable Ethernet. En Modbus TCP, la aplicación solicita la partida o parada, pero es el PLC el responsable de producir el estado real del proceso y contar ciclos. Si el PLC no tiene programado ese comportamiento, el Mini SCADA no puede hacerlo por sí solo.

Seguridad: desconectar el Mini SCADA o cerrar la ventana no garantiza detener el PLC. La lógica del controlador debe definir una condición segura ante una pérdida de comunicación, con parada local independiente y sin depender del software de supervisión. En la unidad se prioriza un proceso simulado mediante marcas y temporizadores del PLC, sin cargas de potencia.
