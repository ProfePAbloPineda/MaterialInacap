Laboratorio 5: Control en Cascada con Modbus TCP/IP

Sistema de Control de Nivel y Flujo - 2 PLCs DVP-SE + Ethernet

⏱️ Duración estimada: 6 horas académicas
👥 Modalidad: Trabajo en parejas
📚 Nivel: Avanzado - Control de Procesos Industriales
🌐 Arquitectura: Red Ethernet TCP/IP + Modbus TCP + Control en Cascada

📋 Criterios de Evaluación que se Desarrollan:

  • 2.1.1 Programa aplicación de control y monitoreo a través de red industrial.
  • 2.1.3 Programa control en cascada para proceso industrial.
  • 2.1.4 Establece comunicación entre equipos del lazo de control, aplicando estrategias de solución en base a la configuración.
  • 2.1.5 Respeta normas de seguridad, higiene y ambiente antes y durante el desarrollo de las actividades.

🎯 Objetivos de la Práctica

  1. Implementar control en cascada con dos lazos de control anidados (nivel → flujo) para proceso de bombeo.
  2. Configurar comunicación Modbus TCP/IP entre dos PLCs Delta DVP-SE usando red Ethernet.
  3. Asignar direcciones IP estáticas a ambos PLCs en la misma subred (192.168.1.x).
  4. Programar PLC Maestro (DVP-SE #1) para control de nivel de tanque superior y gestión de red Modbus TCP.
  5. Programar PLC Esclavo (DVP-SE #2) para control de flujo de bomba y respuesta a comandos del maestro vía Ethernet.
  6. Configurar switch Ethernet industrial para conexión de PLCs y HMIs en red LAN.
  7. Diseñar HMI Maestro para supervisión de nivel, setpoints globales y alarmas del sistema.
  8. Diseñar HMI Esclavo para monitoreo local de flujo, diagnóstico de bomba y control manual.
  9. Intercambiar datos en tiempo real entre PLCs vía Modbus TCP: setpoint de flujo, valor medido de flujo, estado de alarmas.
  10. Implementar estrategia de seguridad con paradas de emergencia, límites de nivel y protección de bomba.
  11. Configurar servidor Modbus TCP en PLC esclavo y cliente Modbus TCP en PLC maestro.
  12. Diagnosticar comunicación Ethernet mediante ping, verificación de conexión TCP y monitoreo de paquetes.
  13. Sintonizar ambos controladores PID (nivel y flujo) considerando la dinámica del sistema en cascada.
  14. Aplicar normas de seguridad industrial en cableado, conexión de equipos y operación del sistema.

📖 Fundamento Teórico

🔗 Control en Cascada (Cascade Control)

El control en cascada es una estrategia avanzada que utiliza dos controladores PID anidados para mejorar el desempeño del sistema cuando existen perturbaciones significativas:

📊 Estructura del Control en Cascada

Ventajas del Control en Cascada: ✓ Rechazo rápido de perturbaciones en el lazo secundario (flujo) ✓ Mejor estabilidad del lazo primario (nivel) ✓ Respuesta más rápida a cambios de setpoint ✓ Menor sobrepico en la variable controlada principal

🌐 Modbus TCP/IP sobre Ethernet

Modbus TCP es la versión del protocolo Modbus adaptada para redes Ethernet TCP/IP. Es el protocolo industrial más utilizado en automatización moderna:

📡 Características de Modbus TCP

Característica Especificación
Capa de transporte TCP/IP (Transmission Control Protocol)
Puerto estándar 502
Medio físico Ethernet (CAT5e/CAT6)
Topología Estrella (vía switch)
Velocidad 10/100/1000 Mbps
Direccionamiento Dirección IP + Puerto
Arquitectura Cliente-Servidor (Master-Slave)
Conexiones simultáneas Múltiples (hasta 8 en DVP-SE)
💡 Ventajas de Modbus TCP vs Modbus RTU:
  • Mayor velocidad: 100 Mbps vs 115.2 kbps máximo de RS-485
  • Mayor distancia: Sin límite práctico (vía routers/switches)
  • Más dispositivos: Sin límite de 32 dispositivos por segmento
  • Integración IT: Compatible con redes corporativas existentes
  • Diagnóstico: Herramientas estándar de red (ping, traceroute)

🗺️ Mapa de Memoria Modbus TCP

Registros Modbus (Holding Registers - 4xxxx): PLC Maestro (IP: 192.168.1.10): 40001: SP_Nivel (Setpoint de nivel) 40002: PV_Nivel (Nivel medido) 40003: Estado_Sistema (Bits de estado) 40004: Alarmas (Código de alarmas) PLC Esclavo (IP: 192.168.1.20): 40001: SP_Flujo_Recibido (Desde maestro) 40002: PV_Flujo (Flujo medido) 40003: Salida_PID_Flujo (0-100%) 40004: Estado_Bomba (Running/Fault) Comunicación Modbus TCP: Maestro (Cliente) → Esclavo (Servidor): - Write Single Register (Función 06): Escribe SP_Flujo en 40001 - Read Holding Registers (Función 03): Lee PV_Flujo desde 40002 Puerto: 502 Protocolo: TCP

📡 Funciones Modbus TCP Utilizadas

Función Código Descripción Uso en esta práctica
Read Holding Registers 03 Lectura de registros Maestro lee PV_Flujo del esclavo
Write Single Register 06 Escritura de un registro Maestro escribe SP_Flujo en esclavo
Write Multiple Registers 16 Escritura múltiple Envío de múltiples setpoints

🔧 PLC Delta DVP-SE con Ethernet

El PLC Delta DVP-SE cuenta con puerto Ethernet integrado que soporta:

  • Modbus TCP Server: El PLC actúa como servidor (esclavo)
  • Modbus TCP Client: El PLC actúa como cliente (maestro)
  • Conexiones simultáneas: Hasta 8 conexiones Modbus TCP
  • Velocidad: 10/100Base-TX

Configuración de Red Ethernet

Parámetro PLC Maestro PLC Esclavo
Dirección IP 192.168.1.10 192.168.1.20
Máscara de subred 255.255.255.0 255.255.255.0
Gateway 192.168.1.1 192.168.1.1
Puerto Modbus 502 502
Modo Modbus TCP Client Modbus TCP Server
💡 Instrucciones de Comunicación Modbus TCP en Delta:
  • RDREGB: Leer registros de dispositivo remoto (función 03)
  • WREGB: Escribir registros en dispositivo remoto (función 06/16)
  • Configuración: Se realiza vía software ISPSoft o registro especial

⚠️ Consideraciones de Seguridad Industrial

Riesgo Medida de Prevención
Choque eléctrico Verificar aislamiento, usar GND común, desconectar antes de cablear
Cortocircuito en red Usar cable Ethernet certificado CAT5e/CAT6, verificar polaridad
Daño por polaridad inversa Verificar polaridad de alimentación 24V DC antes de energizar
Sobrepresión en tanque Válvula de alivio, sensor de nivel alto con parada de emergencia
Operación de bomba en seco Sensor de nivel bajo en tanque de succión con enclavamiento
Ciberseguridad Red aislada, sin acceso a Internet, firewall en switch
⚠️ NORMA DE SEGURIDAD OBLIGATORIA:
  • Siempre usar EPP (Equipo de Protección Personal): gafas de seguridad, guantes dieléctricos
  • Verificar que la alimentación esté OFF antes de realizar conexiones
  • Usar herramienta aislada y en buen estado
  • Mantener área de trabajo limpia y ordenada (5S)
  • Respetar procedimientos de bloqueo/etiquetado (LOTO - Lock Out Tag Out)
  • Aislar red industrial de red corporativa (VLAN o red física separada)

📋 Desarrollo de la Práctica

1 Configuración de Red Ethernet y Cableado

Objetivo: Establecer la conexión física de la red Ethernet entre los dos PLCs, switch y HMIs.

🔌 Diagrama de Conexión de Red

Configuración de Red: IP PLC Maestro: 192.168.1.10 IP PLC Esclavo: 192.168.1.20 IP HMI Maestro: 192.168.1.30 IP HMI Esclavo: 192.168.1.40 IP Laptop: 192.168.1.100 Máscara: 255.255.255.0 Gateway: 192.168.1.1 Cables: - CAT5e/CAT6 con conectores RJ45 - Tipo directo (no cruzado) - Longitud máxima: 100m por segmento

📝 Procedimiento de Cableado

  1. Preparación de cables Ethernet:
    • Usar cables CAT5e o CAT6 certificados
    • Verificar que los conectores RJ45 estén bien crimpados
    • Usar tester de red para verificar continuidad (si está disponible)
    • Longitud recomendada: 1-2 metros para laboratorio
  2. Conexión al switch:
    • Conectar cable del PLC Maestro (puerto ETH) al Puerto 1 del switch
    • Conectar cable del PLC Esclavo (puerto ETH) al Puerto 2 del switch
    • Conectar cable de la Laptop al Puerto 3 del switch
    • Conectar cable del HMI Maestro al Puerto 4 del switch
    • Conectar cable del HMI Esclavo al Puerto 5 del switch
  3. Verificación de LEDs del switch:
    • Cada puerto debe tener LED verde encendido o parpadeando
    • LED apagado = sin conexión (verificar cable)
    • LED naranja = velocidad 10 Mbps (aceptable)
    • LED verde = velocidad 100 Mbps (óptimo)
  4. Configuración de IP en Laptop:
    • Ir a Configuración de Red en Windows
    • Configurar IP estática: 192.168.1.100
    • Máscara: 255.255.255.0
    • Gateway: 192.168.1.1
  5. Prueba de conectividad (Ping):
    • Abrir CMD en laptop
    • Ejecutar: ping 192.168.1.10 (PLC Maestro)
    • Ejecutar: ping 192.168.1.20 (PLC Esclavo)
    • Debe haber respuesta de ambos PLCs
    • Si no hay respuesta, verificar:
      • Cables Ethernet bien conectados
      • LEDs del switch encendidos
      • IPs configuradas correctamente en PLCs
⚠️ VERIFICACIONES DE SEGURIDAD:
  • ✅ Alimentación OFF antes de cablear
  • ✅ Usar EPP (guantes y gafas)
  • ✅ No doblar cables Ethernet más de 90°
  • ✅ Separar cables de red de cables de potencia (mínimo 20cm)
  • ✅ Usar canaletas o organizadores de cable

2 Configuración de Direcciones IP en PLCs

Objetivo: Configurar las direcciones IP estáticas en ambos PLCs DVP-SE.

⚙️ Configuración vía ISPSoft

  1. Abrir ISPSoft y crear nuevo proyecto para PLC Maestro.
  2. Seleccionar modelo DVP-SE en la lista de PLCs.
  3. Ir a Configuration → Device Comment → Ethernet.
  4. Configurar parámetros de red:
    Configuración PLC Maestro (DVP-SE #1): ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ IP Address: 192.168.1.10 Subnet Mask: 255.255.255.0 Default Gateway: 192.168.1.1 Modbus TCP Server: ENABLE Port: 502 Modbus TCP Client: ENABLE Connection 1: Remote IP: 192.168.1.20 Remote Port: 502 Local IP: 192.168.1.10
  5. Configurar PLC Esclavo:
    Configuración PLC Esclavo (DVP-SE #2): ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ IP Address: 192.168.1.20 Subnet Mask: 255.255.255.0 Default Gateway: 192.168.1.1 Modbus TCP Server: ENABLE Port: 502 Modbus TCP Client: DISABLE (no necesita)
  6. Descargar configuración a cada PLC:
    • Conectar USB al PLC Maestro
    • Download → Configuration → Ethernet
    • Repetir para PLC Esclavo
    • Reiniciar ambos PLCs después de descargar
  7. Verificar configuración:
    • En ISPSoft, ir a Online → Connection Setup
    • Seleccionar Ethernet
    • Ingresar IP del PLC (192.168.1.10 o 192.168.1.20)
    • Click en "Test Connection"
    • Debe mostrar "Connection Successful"

🔍 Verificación de Configuración de Red

Comandos de Verificación desde Laptop: 1. Verificar conectividad: C:\> ping 192.168.1.10 Reply from 192.168.1.10: bytes=32 time<1ms TTL=128 C:\> ping 192.168.1.20 Reply from 192.168.1.20: bytes=32 time<1ms TTL=128 2. Verificar puerto Modbus TCP (502): C:\> telnet 192.168.1.20 502 (Debe abrir ventana negra = puerto abierto) 3. Verificar tabla ARP: C:\> arp -a Interface: 192.168.1.100 Internet Address Physical Address Type 192.168.1.10 00-11-22-33-44-55 dynamic 192.168.1.20 00-AA-BB-CC-DD-EE dynamic
💡 Notas Importantes:
  • Ambos PLCs deben estar en la misma subred (192.168.1.x)
  • No puede haber IPs duplicadas en la red
  • El puerto 502 debe estar habilitado en el firewall (si aplica)
  • Los PLCs DVP-SE soportan hasta 8 conexiones Modbus TCP simultáneas

4 Programación del Control en Cascada con Modbus TCP

Objetivo: Implementar los dos lazos PID anidados distribuidos en los dos PLCs con comunicación Modbus TCP/IP.

🎛️ Estrategia de Control Distribuido

💡 Sintonización del Control en Cascada:
  1. Primero sintonizar el lazo secundario (flujo):
    • Poner el lazo de nivel en manual
    • Aplicar escalón en SP_Flujo
    • Ajustar Kp, Ti, Td del PID de flujo
    • Objetivo: respuesta rápida sin sobrepico excesivo
  2. Luego sintonizar el lazo primario (nivel):
    • Cerrar el lazo de flujo (automático)
    • Aplicar escalón en SP_Nivel
    • Ajustar Kp, Ti, Td del PID de nivel
    • Objetivo: nivel estable, sin oscilaciones

6 Pruebas de Comunicación Modbus TCP

Objetivo: Verificar el intercambio de datos entre PLCs vía Ethernet antes de operar el proceso.

🧪 Procedimiento de Prueba

  1. Verificación de conectividad de red:
    • Energizar ambos PLCs y switch
    • Verificar que LEDs de Ethernet en PLCs estén encendidos
    • LED verde fijo = Link activo
    • LED naranja/verde parpadeante = Actividad de red
    • Abrir CMD en laptop y ejecutar:
      C:\> ping 192.168.1.10 Reply from 192.168.1.10: bytes=32 time<1ms TTL=128 C:\> ping 192.168.1.20 Reply from 192.168.1.20: bytes=32 time<1ms TTL=128 C:\> ping 192.168.1.30 Reply from 192.168.1.30: bytes=32 time<1ms TTL=128 C:\> ping 192.168.1.40 Reply from 192.168.1.40: bytes=32 time<1ms TTL=128
  2. Prueba de escritura Modbus TCP (Maestro → Esclavo):
    • En el PLC Maestro, forzar un valor en D400 (ej. K2000)
    • Ejecutar instrucción WREGB
    • En el PLC Esclavo, monitorear D4000 (registro 40001)
    • Verificar que D4000 = D400 (2000)
    • Si no coincide, verificar:
      • IP del esclavo en instrucción WREGB (192.168.1.20)
      • Puerto Modbus (502)
      • Dirección del registro (4000)
      • Conexión Modbus TCP configurada en ISPSoft
  3. Prueba de lectura Modbus TCP (Maestro ← Esclavo):
    • En el PLC Esclavo, forzar un valor en D4001 (ej. K1500)
    • Ejecutar instrucción RDREGB desde el Maestro
    • En el PLC Maestro, monitorear D500
    • Verificar que D500 = D4001 (1500)
    • Si no coincide, verificar:
      • Flag de lectura (M1163)
      • Dirección del registro (4001)
      • Timeout de comunicación (aumentar si es necesario)
      • Firewall o antivirus bloqueando puerto 502
  4. Prueba de comunicación continua:
    • Ejecutar programa completo con RDREGB y WREGB cíclicos
    • Monitorear contador de errores de comunicación
    • Verificar que no haya timeouts (M1051 no debe activarse)
    • Medir tiempo de ciclo de comunicación (debe ser < 50ms)
    • Verificar LEDs de actividad en switch (deben parpadear)
  5. Prueba de recuperación de fallos:
    • Desconectar cable Ethernet del PLC Esclavo
    • Verificar que se active alarma de comunicación (M1051)
    • Verificar que el sistema entre en modo seguro (SP_Flujo = 0)
    • Reconectar cable Ethernet
    • Verificar que la comunicación se restablezca automáticamente
    • El tiempo de recuperación debe ser < 5 segundos
  6. Prueba con software de diagnóstico:
    • Usar software Modbus Poll o Modbus Slave en laptop
    • Configurar conexión a 192.168.1.20 puerto 502
    • Leer registro 40002 (PV_Flujo)
    • Escribir en registro 40001 (SP_Flujo)
    • Verificar que los valores se actualicen en el PLC

📊 Diagnóstico de Errores Comunes en Modbus TCP

Síntoma Causa Probable Solución
Ping no responde IP incorrecta o cable desconectado Verificar IP y LEDs del switch
WREGB no escribe en esclavo IP del esclavo incorrecta Verificar configuración en ISPSoft
RDREGB retorna error Timeout muy corto Aumentar timeout a 3000ms
Comunicación intermitente Cable Ethernet dañado Reemplazar cable, verificar con tester
Datos incorrectos Dirección de registro errónea Verificar mapeo de registros (40001 = D4000)
No hay conexión TCP Puerto 502 bloqueado Verificar firewall, habilitar puerto 502
Múltiples errores CRC Switch defectuoso o congestión Reemplazar switch, verificar tráfico de red
⚠️ INDICADORES DE ESTADO:
  • LED ETH en PLC: Verde fijo = Link activo, Parpadeo = Actividad
  • LED ERROR en PLC: Debe estar apagado (si parpadea, hay error)
  • M1000 (Maestro): Debe estar SET si la comunicación es exitosa
  • M1050: Ethernet Link OK (debe estar activo)
  • M1051: Ethernet Error (debe estar desactivado)
  • M1060 (Esclavo): Modbus TCP Server activo

7 Puesta en Marcha del Sistema

Objetivo: Operar el sistema completo con control en cascada y verificar desempeño.

🚀 Secuencia de Arranque

  1. Verificaciones previas (CHECKLIST):
    • ☐ Nivel de agua en tanque inferior suficiente (mínimo 30%)
    • ☐ Válvulas manuales en posición correcta (abiertas)
    • ☐ Sensor de nivel calibrado (verificar lectura en HMI)
    • ☐ Sensor de flujo calibrado (verificar lectura en HMI)
    • ☐ Bomba sin obstrucciones mecánicas
    • ☐ EPP colocado (gafas, guantes)
    • ☐ Área de trabajo limpia y ordenada
    • ☐ Botón de emergencia accesible y funcional
    • ☐ Red Ethernet activa (LEDs en switch encendidos)
    • ☐ Ping exitoso a ambos PLCs
  2. Energización:
    • Energizar fuente de 24V DC (PLCs y sensores)
    • Verificar que ambos PLCs arranquen sin errores
    • Verificar que HMIs muestren comunicación activa
    • Verificar que LEDs de Ethernet estén activos
    • Energizar fuente de bomba (12V/24V DC)
  3. Modo Manual (pruebas individuales):
    • En HMI Esclavo, seleccionar modo MANUAL
    • Activar bomba manualmente desde HMI
    • Verificar que el flujo aumente gradualmente
    • Verificar que PV_Flujo en HMI coincida con caudal real
    • Detener bomba
    • Abrir válvula de entrada manualmente (Y0)
    • Verificar que el nivel del tanque superior aumente
    • Verificar que PV_Nivel en HMI coincida con nivel real
  4. Modo Automático - Lazo de Flujo:
    • En HMI Esclavo, seleccionar modo AUTO
    • Ingresar SP_Flujo = 50 L/min
    • Activar bomba
    • Observar respuesta del PID de flujo
    • Verificar que PV_Flujo alcance SP_Flujo sin sobrepico excesivo
    • Ajustar parámetros PID si es necesario
  5. Modo Automático - Control en Cascada:
    • En HMI Maestro, seleccionar modo AUTO
    • Ingresar SP_Nivel = 1500 L (75% del tanque)
    • Activar sistema
    • Observar:
      • El PID de nivel calcula SP_Flujo
      • SP_Flujo se envía al esclavo vía Modbus TCP
      • El PID de flujo ajusta la bomba
      • El nivel del tanque se estabiliza en SP_Nivel
    • Verificar en HMI Maestro que PV_Flujo se actualice desde esclavo
    • Monitorear tiempo de respuesta de red (debe ser < 50ms)
  6. Prueba de rechazo de perturbaciones:
    • Con el sistema en estado estable, abrir válvula de salida del tanque
    • Observar cómo el control en cascada compensa:
      • El nivel comienza a bajar
      • El PID de nivel aumenta SP_Flujo
      • SP_Flujo se envía vía Ethernet al esclavo
      • El PID de flujo aumenta velocidad de bomba
      • El nivel se recupera y estabiliza
    • Medir tiempo de recuperación (debe ser < 2 minutos)
  7. Prueba de cambio de setpoint:
    • Cambiar SP_Nivel de 1500 L a 1800 L (90%)
    • Observar respuesta del sistema
    • Verificar que no haya sobrepico (< 5%)
    • Medir tiempo de establecimiento (debe ser < 3 minutos)
💡 Parámetros Típicos de Desempeño:
  • Error en estado estable: < 2% del SP
  • Sobrepico máximo: < 10%
  • Tiempo de establecimiento: < 5 minutos
  • Rechazo de perturbaciones: Recuperación en < 2 minutos
  • Latencia de red: < 50ms (ping + Modbus)
  • Tasa de errores Modbus: < 0.1%

Medida Implementación Verificación

Riesgo Protección Nivel

3. Parada de Emergencia
Circuito de Emergencia (Categoría 0 - Parada Inmediata): Botón E-Stop (NC) ──[X3]──┬──[RST M1000]── (Detener comunicación) │ ├──[RST Y0]───── (Cerrar válvula) │ ├──[RST Y1]───── (Detener bomba) │ └──[MOV K0 D400]─ (SP_Flujo = 0) Características: - Botón de hongo rojo con fondo amarillo - Contacto NC (normalmente cerrado) - Doble canal (redundante) - Enclavamiento mecánico (giro para reset) - Ubicación accesible (máximo 3m del operador) - Reset solo manual (no automático)
4. Ciberseguridad Industrial
Riesgo Medida de Protección
Acceso no autorizado a red Red industrial aislada, sin conexión a Internet
Intrusión en PLCs Contraseña en PLCs, puertos USB deshabilitados
Sniffing de datos Switch con VLAN, red física separada
Modificación de programa Backup de programa, control de versiones
Denegación de servicio Firewall en switch, limitación de conexiones
5. Procedimientos de Bloqueo/Etiquetado (LOTO)
  1. Antes de mantenimiento:
    • Presionar botón de emergencia
    • Desenergizar fuentes de alimentación
    • Colocar candado en breaker principal
    • Colocar etiqueta "PELIGRO - NO ENERGIZAR"
    • Verificar ausencia de voltaje con multímetro
    • Drenar tanques completamente
    • Desconectar cables Ethernet (si es necesario)
  2. Después de mantenimiento:
    • Retirar herramientas y equipos del área
    • Verificar que todas las conexiones estén firmes
    • Retirar candados y etiquetas
    • Restaurar energía gradualmente
    • Verificar operación normal
    • Verificar comunicación de red

Actividad EPP Requerido
Cableado eléctrico Guantes dieléctricos, gafas de seguridad, calzado aislante
Operación del sistema Gafas de seguridad, guantes de nitrilo
Mantenimiento mecánico Gafas de seguridad, guantes de cuero, calzado de seguridad
Manejo de productos químicos (si aplica) Gafas, guantes químicos, delantal, respirador
⚠️ REGLAS DE ORO DE SEGURIDAD:
  1. NUNCA trabajar en equipos energizados sin autorización especial
  2. SIEMPRE verificar ausencia de voltaje antes de tocar conductores
  3. SIEMPRE usar EPP adecuado para la tarea
  4. NUNCA anular o puentear dispositivos de seguridad
  5. SIEMPRE mantener área de trabajo limpia y ordenada
  6. NUNCA operar equipos sin capacitación adecuada
  7. SIEMPRE reportar condiciones inseguras inmediatamente
  8. SIEMPRE aislar red industrial de red corporativa

💡 Análisis de Resultados:
  • Ventaja principal del control en cascada: Rechazo rápido de perturbaciones en el flujo antes de que afecten el nivel
  • Ventaja de Modbus TCP: Mayor velocidad, mejor diagnóstico, más fácil de configurar
  • Desventaja: Mayor complejidad de configuración inicial y costo de equipos
  • Recomendación: Usar Modbus TCP cuando:
    • Se requiera alta velocidad de comunicación
    • Exista infraestructura Ethernet disponible
    • Se necesite integración con sistemas IT/SCADA
    • Se requiera diagnóstico avanzado de red
