Propósito y desafío

Aprendizaje esperado

Implementar y comprobar un sistema físico programado, relacionando entradas, decisiones, repeticiones, selección de alternativas, funciones y comunicación serial.

Se evaluará que el estudiante pueda

  • Interpretar una especificación funcional.
  • Montar y verificar correctamente el hardware.
  • Organizar el programa en funciones.
  • Usar if, switch case y while con sentido.
  • Demostrar y explicar el funcionamiento.

Situación problemática

Una estación debe supervisar una variable de proceso representada por un potenciómetro. En modo automático, tres LED comunican si el valor está en zona baja, media o alta. En modo manual, un operador puede seleccionar los indicadores para comprobarlos.

La estación también debe aceptar órdenes desde el monitor serial del IDE de Arduino, mostrar datos del proceso y permitir cambiar su modo de trabajo.

Importante: esta guía entrega fragmentos y criterios. El programa completo debe ser diseñado, integrado y probado por el estudiante.

Condición de logro

El sistema debe cumplir todas las funciones obligatorias sin reiniciar la simulación y debe responder de forma controlada a cada pulsación y orden serial.

Especificación funcional

Modo AUTOMÁTICO

El potenciómetro representa el valor del proceso.

Lectura A2EstadoSalida
0 a 339Zona bajaLED verde
340 a 699Zona mediaLED amarillo
700 a 1023Zona altaLED rojo

Solo un LED debe permanecer encendido. La selección debe resolverse con una estructura if / else if / else.

Modo MANUAL

  • El potenciómetro continúa siendo leído y puede mostrarse por serial.
  • El botón ACCIÓN avanza: verde → amarillo → rojo → apagado → verde.
  • El botón MODO vuelve a activar el modo automático.
  • La secuencia manual puede resolverse con una variable de estado y switch case.

Comportamiento de los botones

  • Leer el estado del botón antes de evaluarlo con if.
  • Si está pulsado, un while debe releer la entrada mientras continúe en 1.
  • La acción se ejecuta solamente después de detectar la liberación del botón.

Información mínima por serial

  • Modo actual: AUTOMÁTICO o MANUAL.
  • Lectura cruda del potenciómetro.
  • Porcentaje aproximado.
  • Zona o LED activo.
  • Mensajes de confirmación y error.

Menú de supervisión serial

Al iniciar, y cada vez que se solicite ayuda, el monitor serial debe mostrar un menú semejante al siguiente:

===== ESTACIÓN DE MONITOREO =====
1 - Mostrar estado actual
2 - Activar modo AUTOMÁTICO
3 - Activar modo MANUAL
4 - Ejecutar prueba de los tres LED
5 - Apagar salidas y reiniciar estado manual
M - Mostrar nuevamente este menú
Ingrese una opción:

Requisitos del menú

  • Leer una opción solamente cuando Serial.available() > 0.
  • Resolver las órdenes mediante switch (opcion).
  • Informar por serial qué acción se ejecutó.
  • Incluir default para opciones inválidas.

Restricción de diseño

Los botones físicos y el menú serial deben modificar las mismas variables de estado. No se aceptan dos sistemas independientes que se contradigan entre sí.

Ejemplo: si la opción 3 activa MANUAL, el siguiente toque del botón MODO debe regresar a AUTOMÁTICO.

Diagrama de flujo general

Las flechas muestran el recorrido completo del programa. Después de actualizar las salidas, la ejecución vuelve directamente a leer el potenciómetro y continúa el ciclo.

6

Detalle de lectura de un pulsador

El flujo representa directamente el código utilizado en clases. Dentro del while se vuelve a leer el botón; cuando cambia a 0, el ciclo termina y recién entonces se ejecuta la acción.

estado_boton = digitalRead(A0);
if (estado_boton == 1) {
  while (estado_boton == 1) {
    estado_boton = digitalRead(A0);
  }
  // acción del botón
}
