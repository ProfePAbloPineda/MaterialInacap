Antes de comenzar

Un estanque, varias redes, una misma información

Una estación de llenado simulada conecta un PLC físico, un PC con KEPServerEX, otro PC con Infilink y una HMI. Estudiarás cómo viajan sus datos y después construirás esa LAN. Los temas de WAN y nube se abordan conceptualmente, sin exigir equipos ni servicios remotos.

Resultados de aprendizaje

  • Diferenciar alcance de redes y funciones de IP, máscara, MAC, gateway y DNS.
  • Planificar y verificar una LAN para PLC, OPC y SCADA mediante evidencias.
  • Explicar el acceso remoto y proponer una arquitectura TI/TO con controles de seguridad.
  • Reconocer los parámetros de una conexión OPC UA remota y distinguirlos de los usados en la LAN de práctica.

Cómo trabajar

Estudia los diez conceptos y desarrolla solo las tres actividades breves señaladas. Al final, realiza el montaje integrador con el programa entregado por el docente. Las simulaciones representan decisiones de red: no envían paquetes, no detectan equipos y no califican tus respuestas. Tus conclusiones serán revisadas por el docente.

Para estudiar necesitas navegador y un PC Windows con terminal. Para el montaje final necesitas los dos PC, PLC físico con Ethernet, 06XA, HMI, switch, pulsadores y fuente descritos al final. No se requiere VPN ni nube. Trabaja en una red de laboratorio autorizada; los cambios de IP se realizan solo en el adaptador de práctica. No modifiques la red institucional ni el PLC de un proceso real.

Conserva tu trabajo. El guardado automático utiliza este navegador y este archivo, cuando el navegador lo permite. Descarga un respaldo JSON al terminar cada sesión; contiene respuestas e imágenes y permite continuar en otro equipo. El HTML original no se modifica al escribir. Concepto 01

El alcance de una red

El alcance describe el ámbito de interconexión. No indica por sí solo velocidad, seguridad ni protocolo. Una red cableada o inalámbrica puede ser local; Internet es una interconexión global de redes.

TipoÁmbito habitualAplicación en automatización
PAN · Personal Area NetworkEntorno de una persona, normalmente pocos metros.Sensor Bluetooth de mantenimiento conectado a una tableta. No reemplaza automáticamente una red de control.
LAN · Local Area NetworkSala, laboratorio, edificio o instalación bajo administración local.Switch Ethernet con PLC, servidor OPC y SCADA de una planta. Puede tener varias VLAN y subredes.
MAN · Metropolitan Area NetworkInterconecta sedes dentro de una ciudad o área metropolitana.Fibra de un operador que conecta varias estaciones de bombeo urbanas.
WAN · Wide Area NetworkConecta redes a distancias amplias; enlaces públicos o privados.Planta en una región y centro de supervisión en otra, mediante operador y VPN.
No existen límites universales de metros que separen estas categorías. Clasifica por alcance, administración y función, y justifica los casos ambiguos.
Concepto 02

Dirección IP y máscara: ¿a qué red pertenece el equipo?

La dirección IP identifica una interfaz en una red IP y permite encaminar paquetes. Un PC puede tener varias IP por sus adaptadores físicos, virtuales y VPN. IPv4 usa 32 bits, escritos como cuatro números de 0 a 255, por ejemplo 192.168.10.30. IPv6 usa 128 bits en hexadecimal, por ejemplo 2001:db8::30 (prefijo de documentación).

“Tipo de IP” puede referirse a cosas distintas

No todas las direcciones 172.x.x.x son privadas. Tampoco toda IP fuera de estos tres bloques es pública: existen rangos reservados y especiales. Las antiguas clases A/B/C son históricas; aquí se trabaja con prefijos CIDR.

La máscara separa red y host

En 192.168.10.30/24, los primeros 24 bits identifican la red. La máscara es 255.255.255.0. El equipo obtiene la red mediante la operación binaria IP AND máscara.

IP:        192.168.10.30
Máscara:   255.255.255.0 = /24
Red:       192.168.10.0
Hosts:     192.168.10.1 a 192.168.10.254
Broadcast: 192.168.10.255

Para una subred IPv4 convencional, los hosts utilizables son 2^(32−prefijo) − 2. Un /24 ofrece 254 y un /26 ofrece 62. Los prefijos /31 y /32 tienen usos especiales y no se calculan con esa regla general.

Con /26, 192.168.10.30 pertenece a 192.168.10.0/26 y 192.168.10.70 a 192.168.10.64/26: compartir los primeros tres números no basta.

Concepto 03

Dirección MAC: entregar la trama en el enlace local

La MAC identifica una interfaz en tecnologías de enlace como Ethernet. Habitualmente tiene 48 bits y se representa con seis pares hexadecimales, por ejemplo 02:1A:2B:3C:4D:50 (ejemplo administrado localmente). No es una contraseña ni garantiza la identidad de un equipo: puede cambiarse o suplantarse.

El switch aprende en qué puerto recibe tramas con cada MAC de origen. Para un destino conocido, dirige la trama al puerto correspondiente. Si desconoce la MAC de destino, puede inundar la trama dentro de la VLAN; no necesita conocer las IP para conmutar Ethernet básico.

ARP conecta IPv4 con Ethernet

En la misma subred, el SCADA usa ARP para conocer la MAC de la IP del servidor OPC. Si el destino está en otra red, busca la MAC del siguiente salto, normalmente el gateway, no la MAC del servidor remoto. En IPv6 esta función se resuelve mediante Neighbor Discovery.

Destino IPMAC de destino de la primera tramaQué permanece / cambia
OPC 192.168.10.20, misma LANMAC del servidor OPC.La trama llega al servidor a través del switch.
OPC en otra redMAC de la interfaz LAN del gateway.Los routers construyen nuevas tramas por salto. Las IP finales se mantienen normalmente, salvo traducciones como NAT.

Concepto 04

Puerta de enlace: salir de la subred

La puerta de enlace predeterminada es el siguiente salto usado cuando no hay una ruta más específica hacia el destino. Suele ser la IP de un router o firewall en la subred del equipo. Un router une redes IP; un switch Ethernet básico conecta equipos dentro de una red de enlace.

El PC 192.168.10.30/24 alcanza directamente al OPC 192.168.10.20. Para llegar a 192.168.20.53 usa una ruta, por ejemplo vía 192.168.10.1. El router debe conocer cómo llegar al destino y debe existir un camino de retorno permitido.

El gateway no es necesariamente el DNS. No requiere terminar en .1. Una LAN aislada puede comunicar equipos de la misma subred sin gateway ni DNS. Configurar un gateway no crea Internet ni abre reglas de firewall.
Concepto 05

DNS: encontrar una dirección a partir de un nombre

El Domain Name System resuelve nombres en datos como direcciones IP. Un registro A entrega IPv4 y un AAAA entrega IPv6. El resolutor puede usar caché y consultar otros servidores. DNS no transporta la página web, no asigna la IP del PC y no abre los puertos del servidor.

En SCADA, un nombre estable como opc.planta.example evita escribir una IP en cada cliente. Aquí .example es un dominio reservado para ejemplos: no se resolverá en Internet. En una instalación real, el administrador publica el registro en el DNS autorizado.

Una IP puede alojar varios sitios. HTTP utiliza el nombre solicitado y HTTPS depende además de TLS/SNI y del certificado. Un acceso por IP fallido no demuestra que DNS haya fallado. Si abre, tampoco demuestra que todas las webs puedan abrirse por IP. No se requiere instalar Python ni cambiar el DNS del equipo.

Modelo sin caché ni archivo hosts. No establece una conexión real.

Concepto 07

Acceder desde la WAN a una LAN

Una dirección privada no es enrutable directamente desde Internet. Para entrar a una LAN se necesita una arquitectura autorizada: por ejemplo, una VPN hacia un firewall y acceso limitado a un equipo de salto. La VPN aporta un túnel protegido; las reglas siguen definiendo qué se puede alcanzar.

NAT y publicación de puertos

En IPv4, NAT/PAT suele traducir conexiones salientes de varias IP privadas a una IP de salida. Una redirección de puertos traduce una conexión entrante a un equipo interno: publica un servicio; no lo protege ni crea una VPN. Este apartado es conceptual: no debes configurar VPN ni publicar servicios para desarrollar la guía.

En un esquema entrante tradicional se necesita una dirección pública alcanzable, rutas y reglas correctas. Con CGNAT, el operador comparte una dirección pública y el router del usuario normalmente no puede recibir conexiones entrantes mediante su propia redirección. El bloque 100.64.0.0/10 es espacio compartido del operador, distinto de RFC 1918. DDNS actualiza un nombre cuando cambia la IP: no elimina CGNAT ni abre un firewall.

Concepto 08

Red industrial: topología y roles OPC–SCADA

En una red industrial conviven funciones de campo, control y supervisión. La topología física describe conexiones; la lógica describe segmentos, rutas y flujos de datos. Una estrella usa un switch central; un anillo industrial puede ofrecer redundancia si sus equipos y protocolo la soportan. Cerrar un anillo sin configuración apropiada puede generar bucles.

Sensor / actuadorSeñal física
↔
PLCAdquisición + control
↔
Servidor OPCDriver + modelo de datos
↔
Cliente SCADAHMI, alarmas e histórico

Este dibujo muestra flujo funcional. Físicamente, PLC, OPC y SCADA pueden conectarse en estrella al mismo switch; el sensor puede llegar al PLC por una entrada analógica. El SCADA solicita lecturas o suscripciones al OPC; el servidor adquiere datos con un driver compatible. Las escrituras requieren permisos y validación del proceso.

OPC UA y OPC clásico no son intercambiables

OPC UA permite modelos de datos, certificados de aplicación, autenticación de usuario y modos de seguridad. OPC DA clásico se basa en COM/DCOM de Windows y exige otra configuración de red y seguridad. El estudio de nube usa OPC UA cliente/servidor sobre TCP. El montaje final empleará el OPC realmente admitido por Infilink: DA o UA según la versión. OPC UA PubSub requiere otro diseño.

Concepto 09

Ciberseguridad: tecnología operacional conectada con TI

TI administra información y servicios corporativos. TO u OT supervisa o actúa sobre procesos físicos: PLC, HMI, sistemas de control y sus redes. Al conectarlas se deben conservar disponibilidad, integridad y seguridad física, además de confidencialidad. La prioridad concreta depende del riesgo del proceso.

Integrar TO con TI no significa colocarlas en una misma red plana. Se definen zonas según función y riesgo, y conductos con comunicaciones explícitamente permitidas. Una DMZ industrial aloja servicios de intercambio; los firewalls controlan los pasos entre zonas. Una VLAN sola no cifra tráfico ni sustituye reglas de acceso.

Actividad breve 3 · criterio de seguridad

Elige qué comunicar y qué mantener local

Una planta desea compartir tendencias con la oficina. Propone conectar todos los equipos a la misma red y habilitar acceso desde Internet al PLC. Analiza la propuesta sobre papel: no debes instalar VPN, abrir puertos ni disponer de servicios de nube.

Concepto 10

Parámetros para utilizar OPC UA en la nube

“OPC en la nube” puede describir un servidor UA ejecutándose en una máquina remota, o un servicio que recibe datos desde un gateway. No toda plataforma de nube admite OPC UA TCP: algunas reciben MQTT o HTTPS. En ese caso hace falta una pasarela que traduzca o publique datos; escribir una URL web en un cliente OPC no basta.

Define primero la dirección de la conexión

Opción A: el SCADA local es cliente y se conecta a un servidor UA remoto accesible por una ruta privada/VPN. Debes definir cómo ese servidor recibe los datos reales de planta. Opción B: un colector local lee el OPC de planta y establece una conexión saliente hacia la nube con el protocolo admitido. Para el caso didáctico se prefiere supervisión remota de solo lectura; el lazo de control permanece local.

1. Proceso propuesto: estación de llenado simulada

Un estanque de servicio dispone de una bomba de llenado ficticia. Al pulsar Marcha, el PLC activa un estado interno de bomba en marcha. Al pulsar Parada, lo desactiva. La fuente de 0–10 V representa manualmente el transmisor de nivel: 0 V equivale a 0 % y 10 V a 100 %.

Qué es real y qué es simulado. El PLC, las entradas, el módulo y las comunicaciones son reales. El nivel se cambia girando la fuente, no mediante agua. La bomba es una variable interna; no se conecta un motor. Activar “bomba en marcha” no hace subir por sí solo el voltaje ni el nivel. Durante las pruebas, tú representas el llenado aumentando gradualmente la fuente.

Nivel alto / bloqueoProtección simulada por sobrellenado.Con nivel ≥85 %, detiene la bomba y bloquea Marcha. El bloqueo se libera al bajar a ≤80 %, sin rearranque automático.
Bomba en marchaEstado interno del proceso.Tras una parada o bloqueo, exige nueva pulsación de Marcha. En el arranque del PLC comienza detenida.

Entre 80 % y 85 % se conserva el estado del bloqueo anterior. Esta histéresis evita conmutaciones repetidas cerca del umbral. Las condiciones propuestas son la especificación de la maqueta; los pulsadores de práctica no constituyen un sistema de parada de emergencia de una máquina real.

2. Materiales y preparación

  • PLC físico con puerto Ethernet integrado o módulo Ethernet compatible, y módulo 06XA.
  • Dos pulsadores con alimentación y cableado adecuados a las entradas digitales.
  • Fuente regulable de baja tensión, apta para entregar señal estable de 0–10 V, y multímetro.
  • PC1 con KEPServerEX y driver compatible con el PLC; PC2 con Infilink.
  • Pantalla HMI con Ethernet y driver compatible con el PLC; switch de al menos cuatro puertos y cuatro cables Ethernet.
  • Programa y tabla de registros proporcionados por el docente, más software de configuración de la HMI.
Antes de conectar la fuente, confirma el modelo completo del 06XA y su manual. El docente debe indicar los bornes de entrada de voltaje de CH1 y su referencia analógica —habitualmente V+ y COM—, modo, rango y alimentación. Ajusta y mide la señal desde 0 V antes de conectarla. No apliques 24 V al canal analógico, no uses la entrada de corriente como si fuera de voltaje y no supongas que todos los 06XA tienen la misma conversión digital. Los valores crudos del programa se tomarán del manual del módulo instalado.

3. Topología física

Conecta PLC, PC1, PC2 y HMI al mismo switch. PC1 se comunica con el PLC por Ethernet a través de ese switch; no necesitas una segunda tarjeta de red ni un cable exclusivo entre ambos.

8. Montaje y puesta en servicio por etapas

  1. Planificar: identifica modelos, puertos y drivers; recibe programa y mapa de registros. Confirma la modalidad OPC de Infilink y su prueba previa.
  2. Conectar entradas: con el equipo desenergizado realiza el cableado indicado por el docente. Comprueba la fuente de señal y su referencia antes de aplicar tensión al canal.
  3. Armar la estrella: conecta los cuatro equipos al switch y verifica indicadores de enlace.
  4. Asignar IP: configura las direcciones previstas, sin duplicados, y registra IP/máscara de cada equipo.
  5. Verificar red: usa ipconfig /all en los PC y prueba únicamente los equipos asignados. La ausencia de respuesta a ping no demuestra por sí sola una falla de OPC o del driver.
  6. Validar PLC local: con su herramienta de programación, comprueba entradas, lectura analógica, escalado y estados según el programa entregado.
  7. Validar PC1: configura el driver de KEPServerEX y verifica los tags con su herramienta de prueba: valor y calidad. Primero resuelve PLC–KEPServerEX, luego continúa con PC2.
  8. Validar PC2: conecta Infilink al OPC de PC1 según la interfaz confirmada y el procedimiento “Agregar un grupo de tags del OPC de otro PC” incluido más abajo. La IP remota es la de PC1; 127.0.0.1 en PC2 apuntaría a PC2. Comprueba tags antes de terminar las pantallas.
  9. Validar HMI: configura el PLC como dispositivo remoto y lee las mismas variables mediante el driver Ethernet. Comprueba sus dos pantallas.
  10. Comparar y documentar: realiza las pruebas de la tabla siguiente. Corrige una causa cada vez y conserva capturas legibles.
Procedimiento de comunicación · PC2 → PC1

Agregar en Infilink un grupo de tags del OPC de otro PC

Este procedimiento corresponde a la interfaz OPC DA de Infilink que presenta los campos Prog ID y Remote machine (Máquina remota). No es una conexión OPC UA. Si tu versión tiene otra interfaz, utiliza el procedimiento específico confirmado por el docente.

Antes de crear el grupo

  1. En PC1, ejecuta hostname y anota el nombre real del equipo; en el ejemplo se llama PC-OPC. Comprueba que KEPServerEX esté en ejecución y que su cliente de prueba lea correctamente el PLC.
  2. En PC2, confirma su IP y prueba ping PC-OPC, sustituyendo el nombre. Revisa si resuelve a la IP de PC1, por ejemplo 192.168.10.20. Si ICMP está bloqueado puede no haber respuesta; distingue resolución de nombre de respuesta a ping. Si no resuelve o apunta a otra IP, solicita corregir la resolución local.
  3. El docente debe dejar preparados los componentes OPC Classic requeridos, las identidades y los permisos de acceso/activación remota de Windows/DCOM. También debe permitir el tráfico necesario entre esos dos equipos en el firewall; OPC DA no se habilita abriendo únicamente 4840.

Crear el grupo y asociar sus tags

  1. En Infilink de PC2, abre el proyecto en diseño y el panel Tag Groups. Crea un grupo de tipo OPC.
  2. Asigna un nombre propio, por ejemplo OPC_PC1, y una descripción.
  3. En Prog ID selecciona o escribe el identificador real de KEPServerEX instalado en PC1. Un ejemplo para V6 es Kepware.KEPServerEX.V6; confírmalo en el equipo, no lo copies por suposición.
  4. En Remote machine escribe el nombre real de PC1, por ejemplo PC-OPC. No lo dejes vacío ni uses localhost para una conexión remota.
  5. Configura Update Rate, por ejemplo 1000 ms para esta supervisión, y acepta el grupo.
  6. Selecciona ese grupo y crea un tag OPC. Define su nombre local, tipo de dato y Server item con la ruta del tag de KEPServerEX.

Ejemplo ilustrativo de Server item: Planta.PLC.Nivel_Pct, con formato Canal.Dispositivo.Tag. Sustituye los tres componentes por los reales. Si aparece Access path, es opcional según servidor; no dupliques rutas sin necesidad.

Comprobar la lectura antes de diseñar la pantalla

Empieza con un único tag de nivel. Asócialo a un indicador numérico, ejecuta Infilink y modifica suavemente la fuente. Compara su valor con el cliente de prueba de PC1. Cuando cambie correctamente, agrega los estados restantes y las animaciones. Un grupo organiza la conexión; no copia automáticamente el programa PLC ni todas las variables del servidor.
